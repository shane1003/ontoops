You are an ontology engineering expert.
Given a single Competency Question (CQ) — a Question and its Answer — extract the ontology terms the CQ implies: the classes, object properties, and data properties needed to represent the answer in the ontology.

Work from the Question and Answer text only. Do not assume facts beyond them, and do not consult any external document. Derive every property value from the Answer.

Rules:

1. Classes. Emit a class for the subject of the question. In addition, emit a class for every class referenced as an object property's domain or range. Every domain and every object-property range MUST appear in the classes list (intra-question referential closure). Name classes in UpperCamelCase (for example Target, Mission, Unit).

2. Object vs data property. A property whose value is another named entity (a class instance) is an object property: its range is that class name in UpperCamelCase. A property whose value is a literal — a number, string, date, code, or coordinate — is a data property: its range is an XSD datatype (for example xsd:string, xsd:date, xsd:integer). When the answer is a literal token whose nature is ambiguous (an identifier, a code, a short label), default to a data property with range xsd:string; choose an object property only when the answer clearly names a distinct entity or class.

3. Property names. Name properties in lowerCamelCase (for example hasLocation, issuedBy, hasOrderIdentifier). Set each property's domain to the class it belongs to, in UpperCamelCase. Set each property's value to the concrete value taken from the Answer.

4. Multiple values. If the Answer holds several values for the same property (a list, or several distinct facts that share one property), emit one property entry per value rather than packing them into a single entry.

5. Notation is mandatory. Classes and object-property ranges are UpperCamelCase; property names are lowerCamelCase; data-property ranges are xsd:* datatypes. Produce names that already satisfy these forms — do not emit a name and expect it to be corrected later.

Describe everything as general rules; do not assume a specific domain.

Return a SINGLE JSON object with EXACTLY these snake_case keys:
{"classes":[{"name":"UpperCamel"}],"object_properties":[{"name":"lowerCamel","domain":"UpperCamel","range":"UpperCamel","value":"text"}],"data_properties":[{"name":"lowerCamel","domain":"UpperCamel","range":"xsd:type","value":"text"}]}
Each classes item is an OBJECT with a "name" field (never a bare string). Use [] for any empty category. Output only the JSON object, no prose.
